# Bias Audit Report -- Automated Resume Screening Tool (Demo)

> **ALL DATA IN THIS REPORT IS SYNTHETIC.** It was generated by `make_data.py` for demonstration purposes. This report demonstrates audit *methodology* -- it is not a certification of any real system, and it does not satisfy any regulatory filing requirement.

## 1. Scope

- **System under audit:** a logistic-regression resume screener that scores applicants and advances the top 25% to interview.
- **Protected dimensions examined:** sex (gender), race/ethnicity, age band, and the sex x race/ethnicity intersections -- the dimensions NYC Local Law 144 requires in a bias audit.
- **Model inputs:** years of experience, education level, skill assessment score, referral flag, employment-gap months. Protected attributes are *not* model inputs; they are used only by the audit (which is permitted and required to see them).
- **Data:** 7,500 fully synthetic applicants (seed 42), 75/25 train/test split, test set n = 1875.
- **Operating point:** score threshold set so the overall selection rate is 25%.

## 2. Methodology

1. **Selection rate by group:** share of each protected group scoring at or above the operating threshold.
2. **Disparate impact ratio:** group selection rate divided by the highest group selection rate in that dimension. Ratios below 0.80 are flagged under the four-fifths rule.
3. **Calibration by group:** positive predictive value (PPV, precision at the operating threshold) per group, plus calibration curves (`figures/calibration_by_group.png`).
4. **Mitigation comparison:** the same metrics recomputed after (A) per-group threshold tuning and (B) sample reweighting, alongside overall accuracy and AUC so the fairness-accuracy tradeoff is visible.

## 5. Injected bias reference (synthetic ground truth)

Documented in `make_data.py` and `data/generation_config.json`:

- Direct label bias (logits): {"male": 0.45, "white": 0.25}
- Skewed referral rates: {"Male/White": 0.24, "Female/White": 0.16} (default 0.1)
- Age band: no injected bias (control).

## 6. Limitations

- **Synthetic data:** findings describe the generator, not any real hiring process. Effect sizes are illustrative.
- **Single metric family:** this audit covers disparate impact and calibration only -- not equalized odds, individual fairness, or long-term feedback effects.
- **Threshold tuning is a demo technique:** deploying different cutoffs by protected class raises disparate-treatment concerns in real hiring; it is shown here to make the tradeoff measurable, not as production advice.
- **Single operating point:** results are computed at a 25% selection rate; different thresholds change the numbers.
- **Not a certification:** a real Local Law 144 audit requires an independent auditor, historical (not synthetic) data, and publication of results. This repo demonstrates the methodology an auditor would apply.
